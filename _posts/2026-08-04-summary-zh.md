## [SQLite“严重”CVE 被证实是 LLM 生成的假报告](https://research.jfrog.com/post/sqlite-critical-cves-or-llm-slops/) ⭐️ 8.0/10

JFrog 的调查显示，近期报告的 SQLite“严重”漏洞并非真实缺陷，而是由基于 LLM 的工具生成的误报。这一发现揭示了 AI 生成内容可能用不准确的安全报告污染 CVE 数据库。 此事关系重大，因为它降低了漏洞数据库的信噪比，使安全团队更难识别真正严重的问题。同时它也暴露了一种新的攻击途径：恶意行为者可能用虚假报告淹没 CVE 系统，以分散或误导防御者。 JFrog 的文章指出，CVE 数据库缺乏对提交内容的验证是一个系统性问题，LLM 的幻觉被误认为真实漏洞。这一案例凸显了在发布安全公告前进行更严格验证的必要性。

hackernews · ymir_e · Aug 3, 11:28

**背景**: CVE（通用漏洞与披露）是一个公开的已知安全漏洞数据库。LLM（大语言模型）能够生成代码和解释性文本，但它们是概率性的，可能产生听起来合理但错误的结果，即“幻觉”现象。当此类输出被提交为漏洞报告时，就会产生误报，给安全团队带来负担，并侵蚀对 CVE 生态系统的信任。

**社区讨论**: 评论者担心 LLM 生成的报告会降低信噪比，并可能被用来用虚假提交淹没 CVE 系统。有人指出 LLM 也能发现合法的 CVE，还有人将此趋势比作新一代“脚本小子”——他们使用 AI 工具但没有深厚的工程知识。

## [Cloudflare 推出 @cloudflare/computer，融合 isolate 与容器的智能体运行时](https://blog.cloudflare.com/cloudflare-computer/) ⭐️ 8.0/10

Cloudflare 宣布推出 @cloudflare/computer，这是一个新的智能体运行时，可在快速的 V8 isolate 与完整的 Linux 容器之间动态编排，为每个 AI 智能体提供一台属于自己的计算机。这超越了传统意义上将智能体运行在单个容器中的模式。 这一点很重要，因为 AI 智能体通常需要的不只是静态容器来实现有效扩展，而 Cloudflare 的做法可能会改变开发者在成本、性能和部署灵活性之间进行权衡的方式。它直接影响构建和规模化运行智能体工作负载时的基础设施选择。 该运行时会在 Cloudflare 轻量级 isolate（快速且成本高效）与完整 Linux 容器（提供更高的灵活性和隔离性）之间动态选择。虽然公告重点介绍了这一架构机制，但博客文章中并未提供具体的性能基准和定价细节。

## [Cloudflare Workers 现已通过 Spectrum 支持入站 TCP 与 gRPC](https://blog.cloudflare.com/grpc-workers/) ⭐️ 8.0/10

Cloudflare 宣布 Workers 和 Containers 现在可以通过 Spectrum 支持入站 TCP 连接，实现直接转发 socket 到 Durable Objects 和 Containers。开发者因此可以在 Workers 内构建全双工 gRPC 应用，或使用自动的 gRPC 到 gRPC-web 转换功能。 入站 TCP 和 gRPC 支持大幅扩展了在 Cloudflare 无服务器平台上可实现的架构，使实时、有状态和双向通信应用变得可行，而此前这些应用很难或无法实现。这会改变开发者在评估 Workers 与其他无服务器或边缘计算平台时的选型决策。 该功能通过 Spectrum 将 TCP socket 转发到 Durable Objects 和 Containers，为每个连接提供类似服务器的稳定端点。同时包含自动的 gRPC 到 gRPC-web 转换，浏览器端 gRPC 客户端无需再通过独立代理访问服务。

rss · Cloudflare Blog · Aug 3, 13:00

**背景**: Cloudflare Workers 是一种在边缘运行代码的无服务器执行环境，而 Durable Objects 通过将同一对象的请求路由到同一实例，提供有状态的协调计算能力。Spectrum 是 Cloudflare 的 TCP/UDP 代理产品，传统上用于 DDoS 防护和非 HTTP 流量代理。gRPC 是基于 HTTP/2 的高性能 RPC 框架，gRPC-web 则是让浏览器客户端调用 gRPC 服务的适配方案。

## [Meta 将 GEM 训练效率翻倍至 25% MFU，达到 LLM 规模](https://engineering.fb.com/2026/08/03/ml-applications/training-gem-at-llm-scale-meta-ads-recommendation-foundation-model/) ⭐️ 8.0/10

Meta 的生成式广告推荐模型（GEM）是其 Instagram 和 Facebook 广告推荐背后的基础模型，目前已在数千块最新一代 GPU 上以 LLM 规模进行训练。Meta 在 12 个月内将端到端训练效率翻倍至 20-25%的模型 FLOPs 利用率（MFU），同时将训练 FLOPs 扩展了 4 倍。 这一突破表明，大规模广告推荐模型可以达到与前沿 LLM 相当的训练效率，有可能在 Meta 的巨大规模上降低 GPU 成本和训练时间。这些技术很可能对其他大规模模型训练工作具有迁移价值，尤其是在推荐系统和 AI 基础设施领域。 MFU 衡量的是训练期间 GPU 的利用效率，定义为观测吞吐量与理论峰值 FLOPs 下最大吞吐量之比。20-25%的 MFU 意味着相比此前水平翻倍，这一成就又是在一年内将训练算力提升 4 倍、使用数千块 GPU 的情况下取得的。

rss · Meta Engineering · Aug 3, 18:00
