SGLang v0.5.15 发布，针对 Blackwell GPU 上的 GLM-5.2 NVFP4 进行了优化服务，在 8 块 B300 上达到 500+ tok/s/user。它还引入了 Speculative Decoding V2 和 IndexShare 多令牌预测，以提高吞吐量并降低草稿步骤成本。 该发布为高端硬件上的生产级 LLM 服务提供了显著的性能改进，特别是对于大规模部署 GLM-5.2 或类似模型的组织。这些优化展示了 SGLang 对前沿推理效率的承诺。 具体性能数据包括：在 8 块 B300 上达到 500+ tok/s/user，在 4 块 GB300 上达到 450 tok/s/user。Spec V2 实现了 11% 的端到端 TPS 提升，IndexShare MTP 在长上下文下将草稿步骤成本降低高达 1.9 倍。此外，TopK V2 将 top-k 选择与页表变换融合，索引器序言融合将 12 个内核合并为 4 个。

github · Fridge003 · Jul 10, 22:58

## [Cloudflare 智能分层缓存改进公有云源站选择](https://blog.cloudflare.com/smart-tiered-cache-for-public-clouds/) ⭐️ 7.0/10

Cloudflare 宣布智能分层缓存现在支持通过客户提供的云区域提示，为托管在 AWS、GCP、Azure 和 Oracle Cloud 上的源站实现精确的上层选择，从而更准确地将缓存未命中路由到最近的上层数据中心。 这一改进通过确保缓存未命中通过最佳位置的上层进行转发，减少了多云部署的源站负载和延迟，使使用多个公有云和 Cloudflare CDN 的组织受益。 该功能依赖于客户提供的云区域提示，而非基于延迟的检测——后者因共享 IP 范围和全局负载均衡器而对公有云源站不够精确。客户可以明确指定源站的云区域，以实现最佳上层选择。

rss · Cloudflare Blog · Jul 10, 13:00

**背景**: 智能分层缓存是 Cloudflare 的一项功能，通过测量每个 Cloudflare 数据中心到源站 IP 地址的延迟，自动为每个源站选择最近的上层数据中心。上层作为缓存未命中的唯一汇集点，减少源站负载并提高缓存命中率。如果没有明确的区域提示，由于任播和全局负载均衡，公有云 IP 的延迟测量可能不一致，导致次优的层选择。

## [用 Unix 风格工具改进 Copilot 代码评审](https://github.blog/ai-and-ml/github-copilot/better-tools-made-copilot-code-review-worse-heres-how-we-actually-improved-it/) ⭐️ 7.0/10

GitHub 的 Copilot 代码评审团队从定制工具迁移到共享的 Unix 风格代码探索工具，起初导致性能下降，但随后通过重构代理工作流以专注于拉取请求证据而得到改进，最终降低了评审成本。 这表明更好的工具有时会降低 AI 性能，解决方案在于工作流设计；为构建或使用 AI 辅助代码评审工具的团队提供了实用经验。 迁移的关键工具包括 grep、find 和用于 shell 样式模式匹配的 fnmatch；改进源于围绕拉取请求差异和上下文重塑代理的证据收集，而非工具能力本身。

rss · GitHub Engineering · Jul 10, 15:57

**背景**: Copilot 代码评审是 GitHub 的一项功能，可自动审查拉取请求中的问题。Unix 风格工具是可组合的命令行工具（如 grep、find）。最初 GitHub 使用专门的代码探索工具；切换到 Unix 工具后评审变差，直到他们重新设计了代理工作流以更好地利用拉取请求证据。
