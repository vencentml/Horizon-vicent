## [crustc：将整个 Rust 编译器转译为 C 语言](https://github.com/FractalFir/crustc) ⭐️ 7.0/10

经过三年的开发，名叫 FractalFir 的开发者发布了 crustc 项目，该项目将整个 rustc（Rust 编译器）转译为 C 代码，从而无需现有的 Rust 编译器或 LLVM 即可实现引导编译。 该项目解决了 Rust 长期存在的引导编译问题，允许仅使用 C 编译器从源码编译 Rust，并且使得 Rust 能够支持没有 LLVM 或 GCC 后端的晦涩或老旧硬件。 crustc 是一个转译器，它将 rustc 的内部表示（可能是 MIR 或类似 IR）转换为 C 代码，然后可以由任何 C 编译器（如 GCC）编译。该项目仍处于早期阶段，但代表了重大的技术成就。

hackernews · Philpax · Jul 2, 22:57

**背景**: 引导编译一个编译器意味着创建一个自举编译器：从用另一种语言编写的最小编译器开始，来编译用自身语言编写的完整编译器。Rust 目前需要已有的 Rust 编译器（例如预构建的二进制文件）才能从源码编译，这引出了信任和可移植性问题。将 rustc 转译为 C 将允许仅使用 C 编译器从头构建 Rust，从而消除先有鸡还是先有蛋的问题。

## [Linux 6.9 漏洞：LUKS 挂起无法清除密钥](https://mathstodon.xyz/@iblech/116769502749142438) ⭐️ 7.0/10

Linux 6.9 及后续版本的内核存在一个漏洞，导致 cryptsetup luksSuspend 命令在挂起到内存时不再从内核内存中清除磁盘加密密钥。 这一回归削弱了 LUKS 加密的核心安全特性，因为主密钥在系统挂起期间仍存留于内存中，潜在使得拥有物理访问权限的攻击者能够提取这些密钥。 该漏洞专门影响 cryptsetup luksSuspend 操作，该操作最初是 Debian 特定的扩展，可能并非内核上游官方支持的功能。

hackernews · IngoBlechschmid · Jul 2, 15:25

**背景**: LUKS（Linux 统一密钥设置）是 Linux 上的磁盘加密标准。在挂起到内存期间，加密密钥通常必须保留在内存中以便快速恢复；luksSuspend 命令用于临时锁定加密设备，通过从内存中清除密钥并阻止 I/O 直到恢复。该漏洞阻止了密钥清除的发生。

## [单层 Transformer 可与全参数强化学习训练匹敌](https://arxiv.org/abs/2607.01232) ⭐️ 7.0/10

一项新研究发现，单个可训练的 Transformer 层结合基础模型的冻结层，就能达到与全参数强化学习（RL）后训练相当的性能。 这一发现可能大幅降低大型语言模型 RL 微调的计算成本，使 RL 后训练更高效，更易于广泛应用。 该论文的结果因潜在的 token 长度不一致而受到质疑；社区评论指出许多响应在 3K token 限制处被截断，可能影响了结果。

hackernews · tcp_handshaker · Jul 2, 12:10

**背景**: Transformer 模型由多个处理 token 序列的层组成，不同层专注于不同抽象层次。强化学习（RL）后训练用于使模型与人类偏好对齐，但全参数训练会更新所有层，计算成本高昂。该论文研究了哪些层受 RL 影响最大，以及是否可以在不损失性能的情况下冻结大部分层。
