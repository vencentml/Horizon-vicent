## [llama.cpp b10545 修复 Metal Tensor API mat-mat 内核的 K 对齐错误](https://github.com/ggml-org/llama.cpp/releases/tag/b10545) ⭐️ 7.0/10

llama.cpp 的 b10545 版本修复了 Metal Tensor API 矩阵乘法（mat-mat）内核中的一个越界读取错误，该错误在张量 K 维度不是 32 的倍数时出现。现在内核在每次迭代中钳制 K 的范围，只读取有效范围，从而在 Apple Silicon 上消除了 NaN 结果和数据损坏。 此修复对在 Apple Silicon 上运行 K 维度未按 32 对齐的模型的用户尤为重要，可防止 Metal 后端出现无声的输出损坏和 NaN 值。同时，它也体现了 llama.cpp 作为跨平台 LLM 推理栈的不断成熟，对 GPU 计算路径中的边界情况给予了细致关注。 该错误位于 kernel_mul_mm 的 Tensor API 路径中，该路径每次迭代都将静态的 K=32 tile 传给 matmul2d 操作；在最后一个不完整的 tile 上，src1 切片读取超出了张量的 K 范围，导致未定义行为。修复方案让 matmul2d 使用 dynamic_extent，并在每次迭代中将两个操作数的 K 范围钳制为 min(32, K - loop_k)，同时为 K 未对齐的情况新增了 MUL_MAT 测试。

github · github-actions[bot] · Aug 21, 03:49

**背景**: llama.cpp 是一个广泛使用的开源项目，可在 CPU 和 GPU 上本地运行大型语言模型，包括通过 Apple 的 Metal 图形 API 在 Apple Silicon 上运行。Metal Tensor API 路径是 Metal 中较新的计算路径，使用像 matmul2d 这样的张量操作来执行矩阵乘法，对机器学习负载可能更快。当矩阵维度（如 K）不是 tile 大小的倍数时，内核必须显式处理尾部的边缘情况；否则可能导致越界读取和结果损坏。

## [llama.cpp b10534 调整 MVQ→MMQ 解码切换点，提升 CUDA 推理速度](https://github.com/ggml-org/llama.cpp/releases/tag/b10534) ⭐️ 7.0/10

llama.cpp 的 b10534 版本为 MVQ→MMQ 解码切换点增加了按硬件和按量化类型的配置，并新增名为 GGML_CUDA_MMVQ_MAX 的运行时覆盖参数。在 RTX 5090 上，Q4_K 稠密解码在批大小为 8 时吞吐量提升了 23%–41%。 这是对 llama.cpp CUDA 后端的一次具体吞吐量优化，llama.cpp 是使用最广泛的本地 LLM 推理引擎之一。在 Blackwell、Ada 等 GPU 上更快的解码速度，直接提升了众多运行量化模型的用户的每秒 token 数。 新的 GGML_CUDA_MMVQ_MAX 值会被限制在 [1, MMVQ_MAX_BATCH_SIZE] 范围内，因为 mul_mat_vec_q 断言 ncols_dst 不超过该限制；无效输入会发出警告并回退到默认值。默认行为保持不变，并为 DGX Spark 和 Ada（基于 RTX 4090 测试）添加了按硬件默认值，以及一些与 MoE 相关的小调整。

github · github-actions[bot] · Aug 21, 01:37

**背景**: llama.cpp 是一个用于本地运行 LLM 的开源 C/C++ 项目，其 CUDA 后端可在 NVIDIA GPU 上加速推理。在自回归解码过程中，每一步处理一小批 token：mul_mat_vec_q（MVQ）内核专为极小的批大小在 CUDA 核心上设计，而 MMQ 内核使用张量核心，一旦批量足够大就会更快。切换点取决于 GPU 架构和量化类型，这正是 b10534 通过显式切换点和运行时覆盖来调优的内容。

## [博主意外通过废弃 ENUM 域名记录军事基地通话路由](https://lina.sh/blog/hijacking-e164-arpa) ⭐️ 7.0/10

一位名为 lina.sh 的博主通过注册一个废弃的 e164.arpa 区域，意外记录了数十万条打往军事基地的电话路由查询记录。捕获的是呼叫路由信息，而非通话内容。 这一事件表明，废弃的电信基础设施可能被人悄悄重新利用，从而泄露敏感的路由元数据，暴露出电话网络中系统性的安全与隐私漏洞。它也说明，像公共 ENUM 这样被认为已死的协议可能仍在使用中，却无人关注或监控。 ENUM（E.164 号码映射）将电话号码映射到 e164.arpa 域名下的 DNS 名称，被记录的查询可以显示出哪些号码正在被解析以及解析到何处。作者没有部署 SIP 服务器，因此没有实际呼叫被接续或截获；直到涉及军方相关号码之后，该问题才被认真处理。

hackernews · gavide · Aug 21, 13:11

**背景**: ENUM 是 IETF 定义的一种协议（RFC 6116，之前是 RFC 3761），它利用域名系统（DNS）将标准的 E.164 电话号码转换为 SIP URI 等互联网寻址信息，从而在传统电话网络与互联网之间架起桥梁。e164.arpa 区域原本是这种映射的公共基础设施，但公共 ENUM 并未真正普及并逐渐被弃用，尽管如此，一些私有服务仍会通过 VPN 使用类似 ENUM 的查询。这篇博客文章描述了这种基础设施中无人维护的部分如何能被任何人注册，从而变成一个被动记录路由查询的日志器。

## [DeepSeek 发布实验性视觉模型 V4-Flash-Vision-Exp](https://api-docs.deepseek.com/guides/vision/) ⭐️ 7.0/10

DeepSeek 已发布 DeepSeek-V4-Flash-Vision-Exp，这是一个现已在 DeepSeek API 平台上线 的实验性多模态视觉模型。官方称该模型在文本能力上匹敌 DeepSeek-V4-Flash，并在多模态智能体基准测试上实现了大幅跃升。 这标志着 DeepSeek 进入视觉语言模型领域，使开发者可以将图像与文本一起用于推理、OCR 和智能体工作流。它为 GPT-4V、Claude、Gemini 等成熟多模态模型提供了一个具有竞争力的开放 API 选项，有望降低成本并拓展自动化应用场景。 根据 API 文档，图像会根据尺寸被转换为 token，并与文本 token 一起计费；推理前图像会自动缩放：总像素数低于约 384×384 的图像会按宽高比放大，较大图像则缩小至约 800×800。社区测试者指出，这一分辨率对于读取整页 A4 或 Letter 文档等任务可能过低，且至少一次时钟读数测试失败，而一个竞对的小型模型几乎答对。

hackernews · dares2573 · Aug 21, 10:33

**背景**: 视觉语言模型（VLM）是一种能够同时从图像和文本中理解并生成信息的人工智能系统，是对纯文本大语言模型的扩展。OpenAI、Google、Anthropic、Microsoft 等主要厂商都已在其旗舰模型中加入视觉能力，DeepSeek 这款新的实验性变体则为 V4-Flash 文本模型带来了该能力。此前有社区反馈称，早期 DeepSeek 文本模型有时会幻觉出视觉能力，并在实际无法“看见”时虚构出基于文本的图像分析工具。
