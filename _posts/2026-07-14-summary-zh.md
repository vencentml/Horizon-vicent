Scott Willsey 发表了一篇博客文章，详细介绍了如何使用苹果的命令行工具和像 Claude Code 这样的 AI 编码助手，在完全不打开 Xcode 的情况下，通过命令行构建、签名、公证并发布 Mac 和 iOS 应用。 这种工作流程使开发者能够自动化苹果平台的构建过程，并利用 AI 加速开发，但也引发了重要的安全问题：AI 代理直接在开发者机器上运行，可能访问敏感文件。 该方法依赖于苹果的命令行工具，如 xcodebuild、codesign 和 notarize，并且需要一个付费的苹果开发者账号进行代码签名。作者指出，所有步骤都可以编写成脚本并串联起来，由 AI 代理创建该脚本。

## [在 GitHub Actions 中缓存友好地使用 uvx](https://simonwillison.net/2026/Jul/14/uvx-github-actions-cache/#atom-everything) ⭐️ 7.0/10

Simon Willison 分享了一种在 GitHub Actions 中缓存 uvx 工具下载的方法，即设置 UV_EXCLUDE_NEWER 环境变量为某个日期，并将该日期作为缓存键的一部分。 这种优化避免了每次工作流运行时都从 PyPI 重复下载，从而加速了 CI 并减少了网络使用。它提供了一种简单且可重复的方法，既能保持工具更新，又能维持缓存效率。 这个技巧依赖于 UV_EXCLUDE_NEWER 将工具版本固定到特定日期，缓存键包含该日期，因此更新日期会使缓存失效并升级工具。必须在工作流级别设置环境变量。

rss · Simon Willison · Jul 14, 00:56

**背景**: uv 是一个用 Rust 编写的快速 Python 包和项目管理器。uvx 是 `uv tool run` 的别名，用于在隔离环境中临时运行 Python CLI 工具。在 GitHub Actions 中，每次运行通常会重新下载工具，降低工作流程速度。
